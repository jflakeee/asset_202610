# Trailwood 내부 검토와 판매 출고 게이트

원래 상세설계 v1.1의 18절은 **42원형 × A/B = 84개**를 요구한다.
미승인 후보, LOD, 색상 테마, 보조 기둥은 승인된 출고 모델 수에 더하지 않는다.
벤치·테이블·표지판·상자·디딤돌·계단은 유용한 추가물이지만 원래 42원형 목록에
없으므로 정식 범위 변경 없이 누락된 원형 대신 세지 않는다.

```sh
python release_gate.py --channel review
python release_gate.py --channel sales
```

기본 설계 경로는 생성기 폴더의 상위 `original_asset_pack_design_v1.md`다.
다른 위치에서는 `--design /path/to/design.md`를 지정한다. `--root`는 생성 결과가
있는 제작 폴더이며 결과 경로는 `--out`으로 바꿀 수 있다.
종료 코드 0은 선택한 채널의 통과, 2는 차단이다. 판매 차단은 예상된 정상 감사 결과다.

검사는 실제 GLB와 테마 manifest의 경로·중복·SHA-256·개수·테마별 ID 집합,
기존 Khronos 보고서의 모델 커버리지와 오류/경고, 재생성 기준 해시와 기존 성공 기록을
확인한다. 감사 자체가 Khronos 또는 생성기를 다시 실행하지는 않는다. 모델을 수정한
뒤에는 원래 생성·규격·엔진 검사를 먼저 재실행해야 한다. 기존 보고서의 PASS를
새로운 파일의 품질 보증으로 확대하지 않는다.

검토용 묶음은 기술 무결성 검사 통과 시 만들 수 있다. 생성 코드와 미승인 후보를
포함할 수 있으며 사용자가 비교·수정하는 개발 산출물이다. 판매 묶음은 별도 경로
`release_staging/`과 승인 manifest를 사용해야 한다. 현재 파일 존재만으로 판매 허용
상태를 만들지 않으며, 미구현 검증기는 `NOT_VERIFIED`로 남긴다.

판매 출고에 필요한 증거:

- canonical 84개 후보와 파일 해시에 연결된 사람의 형태·팔레트 승인.
- 원형별 출처·도구·참고 목적·AI 사용 단계와 허용 입력 기록.
- LOD별 256×256 네 시점 silhouette IoU 및 누락/예외의 검토 기록.
- 실제 GPU 화면의 재질·그림자·소켓·LOD 전환 검수와 재임포트 시험.
- 설계에서 약속한 .blend 편집 소스, GLB/PNG, 모델 CSV, 문서, 최종 이용조건.
- 예제 6종, 검증 장면, 중립 카탈로그, 승인 모델 썸네일 84장.
- 정확한 canonical 8개만 포함한 Moss 체험판 및 별도 이용조건.
- 판매 staging 파일 허용 목록·크기·해시 검사, 내부 코드/연구 자료 제외.
- 성능 주장을 뒷받침하는 실기기 기록. Android/iOS 검증 전 모바일 최적화 완료 표현 금지.

표본 방향의 지지함수 오차 2% 검사는 픽셀 silhouette IoU 검사와 다르다.
헤드리스 Godot 검사는 실제 GPU 렌더나 Android/iOS 성능 시험과 다르다.
자동 생성기 또는 이 스크립트는 사람의 승인을 생성하거나 대신하지 않는다.
새 증거가 생기면 내용을 검토하여 해당 검증기를 확장해야 하며, 결과 JSON의 상태만
수동으로 PASS로 바꿔서는 안 된다. 업로드·판매 등록은 이 감사의 실행 범위가 아니다.
